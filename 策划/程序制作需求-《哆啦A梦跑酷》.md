## 1. 制作范围与技术栈

### 1.1 制作范围

| 维度 | 要求 |
|------|------|
| 关卡 | 1–20 关，选关分页与星级 |
| 可出战角色 | 哆啦A梦、大雄、静香、哆啦美 |
| 平台 | 横屏 Android APK，可安装运行 |
| 存档 | 单机本地持久化 |
| 货币「+」 | 打开充值说明弹层（美术充值提示页） |
| 携带 | 3 格，规则见策划案 1.7 |

### 1.2 技术栈

| 项 | 要求 |
|----|------|
| 引擎 | Cocos Creator 3.8.x（建议 3.8.8） |
| 语言 | TypeScript |
| 类型 | 2D：界面 + 横版卷轴局内 |
| 屏幕 | 横屏；设计分辨率等比适配 |

## 2. 工程结构

```text
项目根/
├── assets/
│   ├── scenes/
│   │   └── Boot.scene          ← 唯一启动场景
│   ├── resources/
│   │   ├── 素材/
│   │   └── audio/
│   └── scripts/
│       ├── boot/                 ← 启动、全局路由、Toast
│       ├── core/                 ← 应用状态、存档、音频、震动
│       ├── data/                 ← 配表常量（如 GameData.ts）
│       ├── pages/                ← 各主界面与弹层
│       ├── run/                  ← 局内逻辑与表现
│       └── ui/                   ← 通用 UI 组件
```

- **单启动场景 + 代码切页**（Loading / Home / Levels / Run 等）。  
- 图片加载路径与 `resources/素材/` 相对路径一致，例如 `首页/背景图.png`。

## 3. 运行时架构

### 3.1 页面与弹层

| 项 | 要求 |
|----|------|
| 主界面 | Loading、Home、Levels、Run、Result、Inventory、Shop |
| 弹层 | 设置、暂停、商城/背包详情、开箱结果、关于/隐私等；栈式打开关闭 |
| 局内开背包 | 打开背包弹层时局内逻辑暂停 |
| 跳转 | 与策划案第二部分 **2.1** 一致 |

主界面与弹层变更时，通过事件或等价状态订阅驱动 UI 刷新。

### 3.2 存档

| 项 | 要求 |
|----|------|
| 介质 | 本地持久化（localStorage 或引擎等价 API） |
| 内容 | 金币、钻石、角色解锁与出战、道具/箱/钥库存、携带栏、关卡解锁与星级、首通与节点标记、音量震动等设置 |
| 版本 | 存档带版本号；结构升级时做迁移或清档策略 |
| 初始档 | 与配表「表0」及策划案 **1.10** 一致 |

### 3.3 局内

| 项 | 要求 |
|----|------|
| 职责分离 | 局内模拟（移动、跳跃、碰撞、障碍/陷阱、掉落、生命、能量、得分、通关/失败）与画面/HUD/输入分模块实现 |
| 关卡随机 | 同一关卡固定随机种子，重试布局一致 |
| 坐标基准 | 统一设计高度（637）定义地面线、镜头与碰撞，全关口径一致 |
| 规则与数值 | 星级、结算、携带消耗与退回等按策划案 **1.6、1.7、1.9** 及第二部分结算页；数值从配表/数据层读取 |

### 3.4 音频与震动

- 全局一条 BGM 循环；界面与局内按操作播放 SFX。  
- 音量 0–10 与设置联动；震动开关生效，设备不支持时跳过震动。

## 4. 模块功能

对应策划案 **1.3**：

| 模块 | 要求 |
|------|------|
| 加载 | 展示加载进度，完成后进入首页 |
| 首页 | 货币、当前角色；开始（最高解锁关）、选关、商城、背包、设置 |
| 选关 | 20 关、锁定/星级、分页；选关进入局内 |
| 局内 | 跑酷核心、HUD、方向操作、快捷栏（拾取、携带、使用、大招）、暂停与导航 |
| 结算 | 成功/失败界面、星级、得分、奖励；**先完成结算入账再展示 UI** |
| 背包 | 道具/角色/宝箱三 Tab；道具「使用」写入携带栏；开箱扣箱钥并按表随机 |
| 商城 | 三分类、详情、购买扣款、Toast、写存档 |
| 经济 | 成功/失败分层、首通与节点、宝石折算、满星掉落限制（策划案 **1.6**） |
| 携带 | 3 格；局内消耗；未用完携带物结算退回 |
| 设置 | 音量、震动、恢复默认、清缓存（保留玩法进度）、关于/隐私、退出应用 |

按钮区分可点/禁用（禁用态不可点击）；文案长度遵守策划案 **1.4**。

## 5. 配表与程序同步

| 变更类型 | 做法 |
|----------|------|
| 规则 | 更新策划案 → 更新逻辑与 data 层 |
| 仅数值 | 更新 xlsx → 同步 GameData.ts（或读表方案）→ 用配表验收例自测 |
| 流程/UI | 更新策划案第二部分 → 更新对应 pages / boot |

配表为数值主数据源；代码内表与 xlsx 保持一致。

## 6. 完成标准

- 策划案 **2.1** 全部跳转可走通。  
- **1.6–1.9** 经济、携带、关卡与结算与策划案一致。  
- 抽样关卡结算与配表心算例一致（如第 1 关 3 星首通 125 金币）。  
- 横屏下局内快捷栏与主要按钮可操作；杀进程后存档仍在。  
- 细项见策划案 **1.11**。
